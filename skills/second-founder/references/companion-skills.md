# Route work to useful companions

Use a companion to resolve the current paying-customer bottleneck, not because it is installed. Prefer a suitable existing skill, connector or project tool. Select one provider per job, load only its relevant instructions and resources, and install missing guidance on demand under [capabilities.md](capabilities.md). Consult the [companion registry](../assets/companion-registry.json) for verified sources, reviewed pins, exact paths and dependencies; a familiar name or local folder is not installation provenance.

The registry records reviewed versions, not a reason to upgrade an adequate installation. Read the version actually selected. Preserve plugin-managed installations and namespacing; never overwrite a different provider with the same skill name. Skill files, executable dependencies, account connections and permission to act are separate checks. If a needed provider is unavailable, use the stated fallback and continue ready work.

## Give a complete specialist brief

Pass these details together, even when delegating to another agent:

1. **Decision and outcome:** the selected buyer segment, commercial stage, current bottleneck, exact deliverable, bounded scope and how it could affect paying or retained customers.
2. **Evidence and market:** verified product facts, sources/dates, metric windows, unknowns and actual user-versus-payer distinction. Prioritize the saved U.S./UK markets by default while retaining useful opportunities elsewhere; match language, examples and posting windows without inventing local availability or billing currencies.
3. **Execution boundary:** exact project/route/account, permitted reads and mutations, saved authorization reference, no-additional-spend limit, included allowances, data sensitivity, content/audio policy and explicit exclusions. Credential presence is not an allowance or authority grant.
4. **Resources and coordination:** selected provider/version, relevant source files, approved assets, output location, time/effort budget and the parent's run/operation identity. Second Founder retains scheduling, shared-account reservations and authoritative state.
5. **Acceptance and handback:** required factual/visual/code checks, receipts only for authorized completed actions, known limitations, next measurement date and rollback plan when applicable. Return files and evidence plus a clear distinction between findings, proposals, drafts and verified changes.

A specialist may prepare an artifact without owning its external execution. Before any publication or deployment, the parent checks the final artifact, destination, current authority and durable operation state. Do not repeat a side effect because a second skill has its own queue or because the specialist returned an ambiguous result.

Installation adds a capability, not permission to spend, contact people, change prices, alter billing, extract browser sessions, publish private material or relax content restrictions. If a specialist requires an unavailable tool or a new permission, isolate that limitation and continue other ready work; do not silently broaden the task.
